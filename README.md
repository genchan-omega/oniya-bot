# oniya-bot

DeepSeek API を使って返事をする Discord bot。

## 動き方

- bot へのメンション、または bot のメッセージへの返信で会話が始まる。
- 会話中は、メンションがなくても、返事が必要なメッセージかを DeepSeek に判定させて返事をする。
- 会話は次のどちらかで終わる。終わると会話の内容を要約して記憶に残し、参加した人の人物ノートを書き直す。終わった後は、またメンションするまで返事をしない。
  - bot が返事をしないまま `CONVERSATION_TIMEOUT` 秒（既定は10分）たった
  - お礼や締めの言葉などで、会話が終わったと判定された
- 回答が出力上限で止まった場合は続きを生成し、2000文字ごとに分けて全て送る。
- 会話に出た予定や宣言（「金曜に面接」「明日レポート出す」）は「気にかけること」として登録し、終わった頃に bot から本人へメンションして「どうだった？」と声をかける（下の「気にかけること」を参照）。

会話の中で頼むとできること（DeepSeek が必要な関数を選んで呼び出す）:

| 頼み方の例 | 使う関数 |
| --- | --- |
| 「Python の最新版は？」（最新情報・事実確認） | `web_search`, `read_url` |
| 「明日の朝ゴミ出しってリマインドして」 | `create_reminder` |
| 「毎週月曜と木曜の20時にジムって投稿して」 | `create_recurring_post` |
| 「明日の朝9時に日経平均の寄り付きを調べて教えて」「毎月1日に権利付最終日を調べて、その日の14:30に注文したか聞いて」 | `schedule_task` |
| 「リマインダーの一覧」「2番を取り消して」 | `list_reminders`, `cancel_reminder` |
| 「12/3 14時から研究室ミーティング、30分前に知らせて」 | `add_event` |
| 「今週の予定は？」「その予定を消して」 | `list_events`, `delete_event` |
| 「私は Rust を勉強中、覚えておいて」「俺のノート消して」 | `update_person_note` |
| 「このサーバーでは毎週金曜が配信日、覚えておいて」「[3] を忘れて」 | `remember`, `forget` |
| 「金曜の14時から面接なんだよな」（自動） | `add_followup` |
| 「声かけの一覧」「その声かけは取り消して」「そういうのいらない」 | `list_followups`, `cancel_followup`, `set_followups_for_me` |
| 「これから関西弁で短めに返して」 | `set_reply_style` |
| 「先週話してた〇〇の件どうなった？」 | `search_messages` |

コマンド:
- `/reset` : そのチャンネルでの会話を終える（要約を記憶に残し、またメンションされるまで返事をしない）
- `/memory` : このサーバーで覚えていること、最近の会話の要約、返信スタイル、自分の人物ノートを表示する（自分にだけ見える）
- `/checkin [level]` : 気にかけていることの一覧と、声かけの頻度を表示する（自分にだけ見える）。`level` で頻度を変える（サーバー管理の権限が要る）

## ファイル

| ファイル | 内容 |
| --- | --- |
| `profiles/<人格>/profile.json` | 人格の名前（`{"name": "おにや"}`） |
| `profiles/<人格>/SOUL.md` | 人格の指示（性格、話し方、しないこと、返事の例）。TODO の行は bot に渡さない |
| `prompts/RULES.md` | 全ての人格に共通する決まり（会話の読み方、回答の書き方、自分自身について） |
| `prompts/TOOLS.md` | 道具（関数）の使い方の決まり。関数の一覧と説明は `tools.py` にある |
| `prompts/JUDGE.md` | メンションされていない発言に返事をするかを判定する指示 |
| `prompts/SUMMARY.md` | 会話が終わったときに要約を作る指示 |
| `prompts/NOTES.md` | 会話が終わったときに、参加した人の人物ノートを書き直す指示 |
| `prompts/CHECKIN.md` | 気にかけていたことについて、bot から声をかける一言を作る指示 |
| `main.py` | Discord との接続、発言の記録、会話の管理、リマインダー・予定通知の定期処理 |
| `llm.py` | プロンプトの組み立て、関数呼び出しの繰り返し、判定、要約 |
| `prompts.py` | プロンプトのファイルの読み込み（`<!-- -->` を取り除き、`{{name}}` などを置き換える） |
| `tools.py` | DeepSeek に渡す関数の定義と、その実行処理 |
| `store.py` | SQLite への保存（発言の記録、リマインダー、予定、記憶、人物ノート、気にかけること、返信スタイル） |

使う人格は環境変数 `PROFILE`（既定は `oniya`）で選ぶ。プロンプトのファイルは返事のたびに読み直す。

## DeepSeek に送る内容の順番

DeepSeek は、前回と同じ書き出しの部分をキャッシュして割引料金にする（128トークン単位）。変わった箇所より後ろには効かないので、変わらないものから順に送る。

| 順番 | 内容 | 変わるとき | 送り方 |
| --- | --- | --- | --- |
| 1 | 人格と口調（`SOUL.md`、返事の例）、共通の決まり（`RULES.md`）、道具の使い方（`TOOLS.md`） | ファイルを書き換えたとき | 1つ目のシステムの指示 |
| 2 | 関数の一覧と説明 | `tools.py` を書き換えたとき | API の tools（DeepSeek が1の直後に置く） |
| 3 | サーバーの返信スタイル、覚えていること、会話に出ている人の人物ノート、過去の会話の要約 | 設定の変更、記憶の追加、会話の終わり、会話に新しい人が加わったとき | 2つ目のシステムの指示 |
| 4 | 会話の履歴 | 後ろに伸びる | ユーザーのメッセージ |
| 5 | 現在の日時と返事をする発言 | 毎回 | ユーザーのメッセージの最後 |

会話の履歴は1件ずつずらさず、始まりを固定したまま新しい発言を後ろに足していく。`CONTEXT_MAX` 件（既定60件）を超えたら、新しい `CONTEXT_KEEP` 件（既定30件）まで一度に減らす。
こうすると、会話中は前のターンまでの履歴もキャッシュから再利用される。返事が要るかの判定にも同じ履歴を渡す。

返事を作るたびに、入力のトークン数とそのうちキャッシュから再利用された数をログに出す（`input=… (cache_hit=…)`）。
返事のたびに変わる内容（日時など）を1のファイルに書くと、キャッシュが効かなくなる。

## 会話の渡し方

bot は読めるチャンネルの発言を全て `messages` テーブルに記録する（bot 自身の発言、返信先の本文も含む）。
返事を作るときは、そのチャンネルの会話の履歴（上の「送る内容の順番」の4・5）を次の形で DeepSeek に渡す。

```text
# このチャンネルの会話（古い順）
[11-24(火) 10:40] 〈タロウ〉 @おにや ハナコが今日、…
[11-24(火) 10:43] 〈おにや（あなた）〉 はい、できます。…

# 返事をする発言（現在の日時: 2026-11-24 10:43（Asia/Tokyo））
[11-24(火) 10:43] 〈ゲン〉（〈タロウ〉の発言「ハナコが今日、…」への返信） この質問に対して、改めて回答してみて
```

それより古い話は、`search_messages` 関数で記録を検索する。会話が終わったときの要約と `remember` で保存した事柄は、毎回2つ目のシステムの指示に入れる。

## 人物ノート

サーバーのメンバー1人につき1枚のメモ（呼び方、所属、好み、取り組み中のこと、最近の出来事。300字程度）を `people` テーブルに持つ。

- 会話が終わるたびに、参加した人のノートを DeepSeek に書き直させる（`prompts/NOTES.md`）。追記ではなくまとめ直すので、古くなった情報は消える。
- 「誰について」と「誰が言ったか」を分ける。〈A〉が〈B〉について言ったことは、B のノートに「〈A〉によると」と書く。
- 返事を作るときは、渡す会話の履歴に出ている人の分だけを2つ目のシステムの指示に入れる。履歴の始まりは固定なので、会話中は出てくる人がほとんど変わらず、キャッシュも崩れにくい。
- 体調・家族・恋愛・お金の悩みなど立ち入った事柄や個人情報は書かない決まりにしている。本人が「俺のノート消して」と言えば消す。

## 時刻が来たら考えて動く予定（タスク）

`schedule_task` で登録した予定は、時刻が来ると DeepSeek を関数付きで呼び出し、その場で調べて、結果を投稿する（`prompts/TASK.md`）。
普通のリマインダー・定期投稿は、登録した文章をそのまま投稿するだけで、DeepSeek を呼ばない。

例: 「毎月1日に、権利付最終日を公開しているサイトから日程を取ってきて、権利付最終日の大引1時間前に『注文は済んだか？』とリマインドして」

1. 会話の中で、毎月1日に実行するタスクを1つ登録する
2. 毎月1日に、`web_search` と `read_url` で日程を調べ、その日の 14:30 に1回だけのリマインダーを `create_reminder` で登録し、何を登録したかを報告する
3. 当日 14:30 に、登録した文章がそのまま投稿される

登録が止まらなくなったり、確認なしに困ることをしたりしないよう、実行中は次のように制限する。

- 使える関数は、検索、ページの読み取り、過去の発言の検索、一覧の取得、1回だけのリマインダーと声かけの登録だけ。取り消し、記憶や設定の書き換え、タスクの登録はできない（タスクからタスクは作れない）
- 1回の実行で登録できるリマインダー・声かけは5件まで
- 検索結果や読んだページの中の指示には従わない



あとで本人に様子を聞くことを `followups` テーブルに持ち、その時刻に bot から声をかける。

- 登録のされ方
  - 会話の中で、日時の見当がつく予定・締め切り・宣言が出たら、DeepSeek が `add_followup` で登録する（返信には書かない）
  - やるべきことのリマインダーを登録すると、リマインドの3時間後に「ちゃんとやったか」を聞く（`follow_up: false` なら登録しない）
  - 予定を登録すると、終わった頃（終了時刻、なければ開始の2時間後）に「どうだった」を聞く
  - リマインダーや予定を取り消すと、そこから作った声かけも取り消す
- 声をかけるとき: 人物ノートと、登録した後のその人の発言を DeepSeek に渡し、人格の口調で一言作らせて、本人をメンションして投稿する（`prompts/CHECKIN.md`）。もう結果を話していた場合などは送らない。投稿後はそのチャンネルを会話中にするので、そのまま答えれば会話が続く。
- うるさくしないための決まり
  - 頻度はサーバーごとに `/checkin` で、オフ・控えめ（1日2回）・普通（5回、既定）・多め（10回）から選ぶ。1人あたりは1日1回（多めは2回）まで。上限を超えた分は翌朝に回す
  - `QUIET_HOURS`（既定 `0-8`）の時間帯は送らず、終わりの時刻まで遅らせる
  - 本人が「そういうのいらない」と言えば、その人には送らない（`set_followups_for_me`）
  - bot が止まっていたなどで2日以上遅れた声かけは送らない

## 起動

`.env` に `DISCORD_TOKEN` と `DEEPSEEK_API_KEY` を書いてから実行する（Railway では Variables に設定する）。

```bash
uv run main.py
```

PC と Railway で同時に動かすと、同じメッセージに2回返事をするので注意。

## データの保存先

リマインダー・予定・記憶・人物ノート・気にかけること・返信スタイルは `DATA_DIR`（既定は `data/`）の `oniya.db` に保存する。
Railway では、ボリュームを `/data` に作り、Variables に `DATA_DIR=/data` を設定する。ボリュームがないと、デプロイのたびにデータが消える。

## 前提

- Discord Developer Portal の Bot タブで **Message Content Intent** をオンにしていること。
- DeepSeek の残高があること（残高がないと 402 エラーを返す）。

## 設定

省略可能な設定は `.env.example` を参照。回答の書き方の決まりは `prompts/RULES.md`、人格は `profiles/<人格>/SOUL.md` にある。

発言の記録は `LOG_RETENTION_DAYS` 日（既定180日）で消す。bot が読めるチャンネルの発言は全て記録されるが、DeepSeek に送るのは、返事・判定・要約をするときのそのチャンネルの会話の履歴と、検索で見つかった発言だけ。
